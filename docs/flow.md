1. Общие правила
   1.1. Работаем вручную через VS Code и PowerShell, пока без Cursor.

1.2. Интерфейс на русском. Название продукта — BatyaOS.

1.3. После небольшого изменения проверяем типы, затем поведение приложения. Рабочий этап сохраняем в Git.

1.4. Идеи из банка не становятся задачами автоматически. По твоему подтверждению, сейчас в банке есть IDEA-001–IDEA-017. YouTube в текущий план не входит.

2. Этап 1 — активности и журнал
   2.1. Сферы
   Начальный набор:

Карьера.

Фитнес.

Музыка.

Обучение.

Проекты.

Личное.

Можно добавить сферу и удалить пустую. Сферу с содержимым удалить нельзя, чтобы не потерять связанные данные.

«Проекты» и «Личное» присутствуют с начала, но специальные чеклисты появятся на следующих этапах.

2.2. Шаблоны действий
Шаблон определяет:

название;

одну сферу;

тип результата: факт, количество или длительность;

единицу измерения для количественного результата.

Можно создавать и переименовывать шаблоны. Переименование отражается и в старых записях.

Шаблон без записей можно удалить. После появления записей удаление, изменение типа и единицы измерения пока запрещены.

Для фитнеса создаём три шаблона типа «факт»:

Грудь / бицепс.

Спина / трицепс.

Ноги / плечи.

Шаблоны не создают расписание и напоминания.

2.3. Запись активности
Активность — уже совершённое действие. Она содержит:

Поле Правило
Сфера Одна, определяется выбранным шаблоном
Действие Выбор шаблона
Дата Сегодня по умолчанию; можно выбрать прошлую
Результат Факт, целое количество или целые минуты
Заметка Необязательная мысль для дальнейшей обработки
Для длительности вводим минуты, рядом показываем перевод: 90 минут → 1 ч 30 мин · 1,5 часа.

Несколько записей одного действия в один день разрешены. Автоматического объединения нет.

2.4. Форма и журнал
Общая кнопка раскрывает форму над журналом.

После сохранения форма закрывается.

Отмена закрывает форму без добавления записи.

Журнал — таблица под карточками сфер.

Записи сгруппированы по дате, новые сверху.

Есть фильтр по сфере.

Редактирование открывает ту же форму с заполненными полями.

Удаление можно отменить в течение 10 секунд.

Заметка удаляется и восстанавливается вместе с активностью.

На этом этапе данные ещё сбрасываются после перезапуска. Целей, прогресс-баров и музыкальных интеграций пока нет.

3. Этап 2 — постоянное сохранение

### Принятые решения

- SQLite и работа с базой данных отложены. На текущем этапе данные активностей и фильтр по сфере сохраняются в `localStorage`.
- Отмена удаления в течение 10 секунд не реализуется: перед удалением уже отображается диалог подтверждения.
- После импорта JSON показывается количество добавленных новых записей.

  Сохраняем локально:

сферы;

шаблоны;

активности и заметки.

Проверяем, что данные восстанавливаются после закрытия и повторного запуска. Чеклисты и остальные сущности следующих этапов также будем подключать к этому хранению по мере добавления.

Без аккаунтов и облачной синхронизации.

4. Этап 3 — личный чеклист
   4.1. В «Личном» можно создавать, редактировать, удалять и завершать задачи.

4.2. Конкретные задачи на день или неделю заранее не назначаем. Они находятся в общем списке.

4.3. Галочка фиксирует сегодняшнюю дату завершения. Снятие галочки возвращает задачу в незавершённые и убирает её из выполненных показателей. Историю переключений не храним.

4.4. Завершение задачи не создаёт отдельную активность в журнале.

4.5. Долю завершённых задач всего списка показываем отдельно от дневного и недельного выполнения плана.

5. Этап 4 — проекты с подзадачами
   5.1. В сфере «Проекты» можно создать несколько проектов. BatyaOS — один из них.

5.2. У проекта один уровень подзадач, без вложенности и весов.

5.3. Прогресс проекта:

text
Выполнено 3 из 8 подзадач.
Проект без подзадач показывает «Нет задач».

5.4. Сводный прогресс списка проектов считается по всем их подзадачам. Сам проект не даёт дополнительный балл поверх выполненных подзадач.

5.5. Дата завершения и снятие галочки работают так же, как в «Личном». Автоматических записей в журнале нет.

6. Этап 5 — планы и прогресс сфер
   6.1. Основные показатели
   Сфера Основной показатель
   Карьера Количество отправленных резюме
   Фитнес Количество тренировок
   Музыка Минуты практики
   Обучение Минуты обучения
   Личное Количество завершённых задач
   Проекты Количество завершённых подзадач
   Для активностей в расчёт входят только выбранные шаблоны. Например, новый шаблон «Прогулка» не начинает автоматически закрывать план тренировок.

6.2. Дневной и недельный план
Плановые значения задаёшь ты.

Дневной показатель — за выбранную дату, по умолчанию сегодня.

Недельный — за календарную неделю этой даты, с понедельника по воскресенье.

Дневной план может отсутствовать: тогда показываем факт и «План не задан», без условного процента.

Для активностей дневной и недельный планы можно задавать отдельно.

Для «Личного» и «Проектов» недельный ориентир — заданный тобой дневной план × 7. Выполненные задачи суммируются по датам завершения.

6.3. Перевыполнение
text
План: 30 минут.
Факт: 45 минут.

Полоса: заполнена.
Подпись: 45 / 30 мин · 150%.
Факт не обрезаем. На следующий день автоматически ничего не переносим, но весь результат учитываем в неделе.

7. Этап 6 — песни и история практики
   7.1. В «Музыке» есть постоянный список песен, которые хочется разобрать.

7.2. Песню добавляем вручную. Ссылка на Songsterr необязательна и открывается в браузере.

7.3. Песню можно отметить разобранной. Она остаётся в завершённых и не увеличивает прогресс сферы.

7.4. В активности можно выбрать несколько песен для истории или не выбрать ни одной. Музыкальная практика не обязана быть работой над песней.

8. Этап 7 — обработка заметок
   Отдельная вкладка показывает заметки к активностям:

текст;

дату;

сферу;

связь с исходной активностью;

отметку «Отработано».

Это мысли для дальнейшего действия. До появления вкладки они уже сохраняются внутри активностей.

9. Отложенное
   Исследование поиска песен через Songsterr — отдельная задача, без обещания конкретного способа интеграции.

Архивирование использованных шаблонов — позже.

Аналитика, AI, уведомления, облако и прочие идеи — только после отдельного решения.

Перед выпуском возвращаемся к оставшимся предупреждениям зависимостей, политике безопасности и проверке установщика.

10. Что делаем непосредственно следующим
    Начинаем с модели данных этапа 1, а не со всего scope сразу:

Описываем сферу.

Описываем шаблон действия.

Описываем три варианта результата активности.

Создаём файл типов и проверяем его через npm run typecheck.

Форму, журнал и хранение в этот первый шаг не включаем. Согласование завершено — можно переходить к небольшим изменениям кода.
