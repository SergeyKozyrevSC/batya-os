4. Этап 3 — личный чеклист

6.2. Дневной и недельный план
Плановые значения задаёшь ты.

Дневной показатель — за выбранную дату, по умолчанию сегодня.

Недельный — за календарную неделю этой даты, с понедельника по воскресенье.

Дневной план может отсутствовать: тогда показываем факт и «План не задан», без условного процента.

Для активностей дневной и недельный планы можно задавать отдельно.

Для «Личного» и «Проектов» недельный ориентир — заданный тобой дневной план × 7. Выполненные задачи суммируются по датам завершения.

## Правила общения и работы

- Работаем короткими итерациями.
- Нумерация шагов: **0** — краткий статус итерации; далее **1, 2, 3…** — конкретные действия.
- Перед каждым кодовым блоком — пояснение, что и зачем меняем.
- Каждая терминальная команда — отдельным блоком.
- После изменений напоминать сохранить файлы.
- Не считать проверки пройденными без подтверждения пользователя.
- `ок`, `ok`, `щл`, `jr` означают: проверка прошла, можно переходить к Git.
- Не использовать `npm run lint -- --fix`.
- Не менять без отдельной необходимости:
  - модалку удаления активностей;
  - окно Electron в `src/main.ts`.
- Не гадать по коду: если контекст неточен, запросить точный фрагмент или вывод команды.
- Порядок Git после подтверждения:
  1. `git add <конкретные файлы>`
  2. `git diff --cached --stat`
  3. `git commit -m "..."`
  4. `git push origin main`
  5. `git status`

## Текущие типы

В `src/types.ts` уже есть:

```ts
export type ActivitySpherePlan = {
  sphereId: EntityId;
  source: 'activities';
  templateIds: EntityId[];
  metric: 'count' | 'quantity' | 'minutes';
  dailyTarget: number | null;
  weeklyTarget: number | null;
};

export type TaskSpherePlan = {
  sphereId: EntityId;
  source: 'tasks' | 'projectTasks';
  dailyTarget: number | null;
};

export type SpherePlan = ActivitySpherePlan | TaskSpherePlan;
```

`Activity` содержит `templateId`, `date`, `result` и `note`. Запись активности означает выполненное действие; отдельного флага завершения у активности нет.

## Текущая логика плана сферы

- В `App.tsx` есть `updateActivitySpherePlan`, `handleToggleSphereTemplate`, `handleSphereDailyTargetChange`.
- Они должны находиться **в теле компонента `App`**, а не внутри `exportActivities`.
- Важно: ранее блок случайно вставили внутрь `exportActivities`; это уже исправлено и проверено.
- `ActivitySpherePlan` должен быть импортирован из `./types`.
- Для нового плана сферы тип значения по умолчанию явно указан как `ActivitySpherePlan`, иначе TypeScript расширяет `'activities'` и `'count'` до `string`.
- Пока метрика плана сферы фиксированная: `count`.
- Счётчик меняется только при добавлении активности по отмеченному шаблону с сегодняшней датой.
- Снятие шаблона убирает его активности из расчёта текущего показателя.
